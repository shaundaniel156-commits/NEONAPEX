# THE LAST PROMISE — Blender project

A five-minute 3D animated short film built entirely by Python scripts in Blender 4.0:
procedural characters (Daniel, Grace, Brian), four Kampala sets, keyframed animation,
lip-sync, cinematic cameras, synthesised music and sound effects, subtitles, and FFmpeg
assembly into an H.264 MP4.

## Layout

```
The_Last_Promise/
  blender/            characters.blend, sample.blend, scene1..6.blend (generated by the scripts)
  scripts/
    lib/              blib.py (helpers), charlib.py (characters + rig + face), anim.py (walk/gesture/lip-sync),
                      cinema.py (camera, render settings), env_home.py, env_street.py, env_market.py,
                      env_bedroom.py, screenplay.py (every line of dialogue), scenebase.py (scene runner)
    audio/            make_dialogue.py (voice tracks), make_music.py, make_sfx.py, synth.py
    build_characters.py   builds the three characters, renders a line-up + face close-ups
    build_sample.py       the 20-second approval sample
    scene1.py .. scene6.py   the film, one script per scene
    assemble.py           frames + audio + subtitles -> MP4 (per scene and the full film)
    render_all.sh         renders every scene at the chosen resolution, then assembles
  audio/dialogue/     generated/ (placeholder voices), recorded/ (drop real recordings here), lines.json
  audio/music/        warm, hopeful, tender, tense, sad, resolve, triumph (.wav, synthesised)
  audio/sound_effects/ footsteps, keys, rain, thunder, street, market, phone, notification ...
  subtitles/          .srt per scene and for the full film (generated)
  renders/            frames per scene (frame_0001.png ...), timing.json, test stills
  final/              sample.mp4, The_Last_Promise.mp4
  references/         the two reference videos (visual direction)
  documentation/      this README and the Phase 1 report
```

## Requirements

* Blender 4.0 (`apt install blender` on Ubuntu 24.04) — headless rendering with Eevee needs an
  X server, so commands are run through `xvfb-run -a`.
* FFmpeg with libx264, libass (subtitles) and AAC.
* Python 3 with numpy (for the audio generators); espeak-ng for the placeholder voices.

## Rebuilding everything

```bash
python3 scripts/audio/make_dialogue.py      # placeholder voices + lines.json (durations drive timing)
python3 scripts/audio/make_music.py         # procedural score beds
python3 scripts/audio/make_sfx.py           # sound effects + ambience beds
xvfb-run -a blender -b --python scripts/build_characters.py -- 1280 720   # line-up + face stills
xvfb-run -a blender -b --python scripts/build_sample.py -- 1280 720 render  # 20 s sample frames
python3 scripts/assemble.py sample          # final/sample.mp4
```

Render a scene (preview 640x360, or 1280x720 / 1920x1080):

```bash
xvfb-run -a blender -b --python scripts/scene3.py -- 640 360 render
python3 scripts/assemble.py scene3
```

Render the whole film and assemble it:

```bash
bash scripts/render_all.sh 640 360     # preview
bash scripts/render_all.sh 1920 1080   # final quality (see timings below)
```

Test a few frames of a scene without rendering it all:

```bash
xvfb-run -a blender -b --python scripts/scene2.py -- 960 540 frames=24,240,600
```

Each scene script also saves `blender/sceneN.blend`, which can be opened in Blender's UI to
inspect or hand-edit the animation, cameras and lights.

## Render cost (this machine: 4 CPU cores, no GPU, software OpenGL)

| Profile | Eevee samples | seconds / frame | full film (7,200 frames) |
|---------|---------------|-----------------|--------------------------|
| 640 x 360 preview | 6 | ~1.0–1.6 | ~2–3 h |
| 1280 x 720 | 12 | ~3.4 | ~7 h |
| 1920 x 1080 final | 24 | ~11 | ~22 h |

With a GPU (any recent NVIDIA/AMD card) Eevee renders the 1080p profile at well under a
second per frame, so the final render takes minutes rather than a day. Use
`render_all.sh 1920 1080` on such a machine; nothing else changes.

## Voices

The dialogue files are espeak-ng placeholders (clearly synthetic). They are distinct per
character and are what the lip-sync and subtitle timing are built from. To use real
recordings, put WAVs with the same names into `audio/dialogue/recorded/` (for example
`s3_02_grace.wav`), re-run `make_dialogue.py` (it re-measures the durations) and re-run the
scene scripts and `assemble.py`. The mix ducks nothing automatically; music beds are at
~−12 dB relative to dialogue so speech stays clear.

## Editing the film

* Dialogue text: `scripts/lib/screenplay.py` (keep the ids stable).
* Blocking / acting / camera: the `scripts/sceneN.py` files — every action is a line such as
  `A.walk(G, 18.0, 21.5, [...])`, `ctx.say(D, 's1_01_daniel', 11.4, expression_name='smile')`,
  `cam.shot(10.6, 15.0, pos, look, fov=30)`. Times are seconds from the start of the scene.
* Characters: `charlib.SPECS` (colours, clothing, face shape); the same builder makes all three.
* Sets: `env_*.py`.
